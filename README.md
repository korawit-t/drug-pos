# Drug POS

ระบบขายหน้าร้านยาแบบ open source สำหรับร้านยาในประเทศไทย (ต้นแบบ)
รายละเอียดการออกแบบอยู่ใน [DESIGN.md](DESIGN.md)

> ต้นแบบนี้ยังไม่ผ่านการตรวจสอบกับร้านจริงหรือกับแบบฟอร์ม ขย. ฉบับทางการ ร้านต้องตรวจความถูกต้องของรายงานเองก่อนใช้งานจริง

## ความสามารถ

- ขายหน้าร้านด้วยคีย์บอร์ด/เครื่องสแกนบาร์โค้ด, ขายได้หลายหน่วย (เม็ด/แผง/กล่อง)
- ราคา 5 ระดับ ตามกลุ่มลูกค้า
- ตัดสต็อกแบบ FEFO ตาม lot, ล็อกไม่ให้ขายยาหมดอายุ
- ยาอันตราย/ยาควบคุมพิเศษต้องให้เภสัชกรยืนยันด้วย PIN
- แจ้งเตือนแพ้ยาอัตโนมัติตามกลุ่มยา (เช่น แพ้ Penicillin → เตือน Amoxicillin) รวมถึงกลุ่มที่อาจแพ้ข้ามกัน — เภสัชกรต้องใส่ PIN และเขียนเหตุผลก่อนจ่าย
- รับเงินสด หรือโอนผ่าน QR พร้อมเพย์
- พิมพ์ใบเสร็จ 80 มม. และฉลากยา 8×5 ซม.
- พักบิล, ยกเลิกบิล (ต้องใช้ PIN เภสัชกร), สรุปยอดขายรายวัน
- รับยาเข้า: สแกนเพิ่มรายการ, พิมพ์วันหมดอายุตามกล่อง (`03/2028`, `03/71`, `31/03/2571`), บันทึกร่างไว้ทำต่อ, ดึงราคาทุนครั้งล่าสุด, กันบันทึกใบกำกับซ้ำ
- รายงาน ขย.9, ขย.11, ยาหมดอายุ/ใกล้หมดอายุ
- นำเข้าข้อมูลยาและยอดยกมาจาก Excel/CSV พร้อมไฟล์ตัวอย่าง ตรวจไฟล์ก่อนบันทึกเสมอ และนำเข้าซ้ำเพื่ออัปเดตราคาได้
- หลังร้าน (Django admin): ยา, หน่วยขาย, ราคา, ลูกค้า, ผู้ใช้, PIN

## ทดลองบนเครื่องพัฒนา (Mac / Linux)

ต้องมี Python 3.13 และ Node.js 20 ขึ้นไป

```bash
cd backend
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver
```

อีกหน้าต่างหนึ่ง:

```bash
cd frontend
npm install
npm run dev
```

เปิด http://localhost:5173 (หน้าขาย) — หลังร้านอยู่ที่ http://localhost:8000/admin/

ผู้ใช้ตัวอย่างจาก `seed_demo`:

| ผู้ใช้ | รหัสผ่าน | PIN | บทบาท |
|---|---|---|---|
| admin | admin1234 | – | เจ้าของร้าน (เข้าหลังร้านได้) |
| staff | staff1234 | – | พนักงานหน้าร้าน |
| pharm1 | pharm1234 | 1234 | ภก.สมศรี ใจดี |
| pharm2 | pharm1234 | 5678 | ภญ.วิไล รักษ์ยา |

ลูกค้าตัวอย่าง "นักศึกษา" แพ้ Penicillin (ลองขาย Amoxicillin) และ "สมชาย" แพ้ Aspirin (ลองขาย Ibuprofen)

ข้อมูลยาตัวอย่างเป็นข้อมูลสมมติ บาร์โค้ดขึ้นต้นด้วย 200 เช่น `2000000000028` (Paracetamol แผง), `2000000000042` (Amoxicillin แผง)

### หน้านำเข้าข้อมูล

เปิดจากลิงก์ "นำเข้าข้อมูล" ด้านบนขวา (เฉพาะผู้ดูแลร้าน) หรือ `/#/import`

1. ดาวน์โหลดไฟล์ตัวอย่าง `.xlsx` (มีชีตคำอธิบายทุกคอลัมน์)
2. กรอกข้อมูล **1 แถว = 1 หน่วยขาย** ยาตัวเดียวกันที่ขายหลายหน่วยให้ใช้ชื่อการค้าและความแรงเดียวกัน
3. กด "ตรวจไฟล์" ดูว่าจะเพิ่ม/แก้อะไร แล้วค่อย "นำเข้าจริง" — ถ้ามีแถวผิดแม้แถวเดียว จะไม่บันทึกอะไรเลย

ติ๊ก "นำเข้ายอดยกมาด้วย" เมื่อจะนับสต็อกที่มีอยู่เข้าระบบครั้งแรก (ยอดยกมาจะถูกบวกเพิ่มทุกครั้งที่นำเข้า อย่านำเข้าไฟล์เดิมซ้ำ)

### หน้ารับยาเข้า

เปิดจากแท็บ "รับยาเข้า" ด้านบน (หรือ `/#/receive`)

1. เลือกผู้ขาย กรอกเลขที่ใบกำกับ
2. สแกนบาร์โค้ดของกล่อง/แผงที่รับเข้า (สแกนกล่องเดิมซ้ำ = นับเพิ่ม)
3. กด `Tab` เข้าไปกรอกรายการล่าสุด แล้วกด `Enter` ไล่ช่อง: จำนวน → lot → วันหมดอายุ → ราคาทุน → กลับมาสแกนต่อ
4. "บันทึกร่าง" ถ้ายังไม่เสร็จ หรือ "บันทึกเข้าสต็อก" เมื่อครบ (บันทึกแล้วแก้ไม่ได้ และลง ขย.9)

วันเริ่มใช้ระบบ ให้ติ๊ก "ยอดยกมา" แล้วนับยาที่มีอยู่บนชั้นเข้าไป (ไม่ลง ขย.9 และรับของหมดอายุได้)

## ติดตั้งในร้าน (Windows)

> สคริปต์ Windows ยังไม่ได้ทดสอบบนเครื่อง Windows จริง

1. บนเครื่องพัฒนา: `cd frontend && npm run build` แล้ว copy ทั้งโฟลเดอร์โปรเจกต์ (รวม `frontend/dist`) ไปที่เครื่อง server
2. เครื่อง server: ติดตั้ง Python 3.13 จาก python.org แล้วรัน `scripts\windows\setup.bat` (จะให้สร้างบัญชีเจ้าของร้าน)
3. รัน `scripts\windows\start-server.bat`
4. ตั้งค่าเครื่อง server:
   - **IP คงที่**: จอง IP ให้เครื่องนี้ใน router
   - **Firewall**: เปิด port 8000 ขาเข้า (Private network)
   - **ห้ามหลับ**: Power plan → Sleep: Never
   - **Windows Update**: ตั้ง Active hours ให้ครอบเวลาร้านเปิด
   - **รันเป็น service** (เปิดเครื่องแล้วขึ้นเอง ไม่มีหน้าต่างให้เผลอปิด): ใช้ [NSSM](https://nssm.cc) ชี้ไปที่ `start-server.bat`
5. เครื่องหน้าร้าน: แก้ IP ใน `scripts\windows\counter-kiosk.bat` แล้ววาง shortcut ไว้ที่ desktop
6. หลังร้าน (`/admin/`): ตั้งข้อมูลร้าน, เบอร์พร้อมเพย์, ชื่อระดับราคา, เพิ่มผู้ใช้และตั้ง PIN เภสัชกร
7. นำเข้าข้อมูลยาและยอดยกมาจาก Excel ที่หน้า "นำเข้าข้อมูล" (หรือบันทึกยอดยกมาทีละรายการที่หน้ารับยาเข้า)
8. ตรวจความปลอดภัย: `backend\.venv\Scripts\python backend\manage.py check_security`
9. **สำรองข้อมูลทุกวัน**: ตั้ง Task Scheduler ให้รัน `scripts\windows\backup.bat D:\DrugPOS-backup` (หรือโฟลเดอร์ Google Drive) — ห้าม copy ไฟล์ฐานข้อมูลตรง ๆ ตอนระบบทำงานอยู่

หลัง build frontend ใหม่ทุกครั้ง ให้รัน `backend\.venv\Scripts\python backend\manage.py collectstatic --noinput`

### ความปลอดภัยก่อนเปิดใช้จริง

- **เปลี่ยนรหัสผ่านทุกบัญชีและ PIN ของเภสัชกร** รหัสตัวอย่างในไฟล์นี้เป็นข้อมูลสาธารณะ ใครก็อ่านได้
- รันด้วย `DRUGPOS_DEBUG=0` (`start-server.bat` ตั้งให้แล้ว) ไม่เช่นนั้นหน้าจอ error จะเปิดเผยรายละเอียดภายในระบบ
- `python manage.py check_security` ตรวจสองข้อข้างบนให้อัตโนมัติ และเซิร์ฟเวอร์จะเตือนตอนเปิดถ้ายังไม่ได้แก้
- `seed_demo` จะไม่ยอมรันบนเครื่องที่ตั้ง `DRUGPOS_DEBUG=0` เพื่อไม่ให้ข้อมูลตัวอย่างหลุดเข้าเครื่องจริง
- ระบบออกแบบให้อยู่ใน **LAN ของร้านเท่านั้น** ยังไม่มี HTTPS จึงไม่ควรเปิด port ออกอินเทอร์เน็ตหรือ forward จาก router

### เครื่องพิมพ์

- Chrome ที่เปิดด้วย `--kiosk-printing` จะพิมพ์ไปที่ **เครื่องพิมพ์ default** โดยไม่ถาม
- ถ้าเครื่องหน้าร้านเครื่องเดียวต่อเครื่องพิมพ์ใบเสร็จและฉลากพร้อมกัน ตอนนี้ยังเลือกเครื่องพิมพ์แยกไม่ได้ (ทางออกในอนาคต: ห่อหน้าจอเดิมด้วย Electron)
- ตั้งขนาดกระดาษใน driver: ใบเสร็จ 80 มม., ฉลาก 80×50 มม.

## โครงสร้างโปรเจกต์

```
backend/
  config/      settings, urls, รวม API
  core/        ข้อมูลร้าน, วันที่ พ.ศ., QR พร้อมเพย์, สำรองข้อมูล, ข้อมูลตัวอย่าง
  accounts/    ผู้ใช้, บทบาท, PIN เภสัชกร
  inventory/   ยา, หน่วย, ราคา, lot, ledger สต็อก, ใบรับยา, กลุ่มยาแพ้, นำเข้าจาก Excel
  sales/       ลูกค้า, ขาย, ยืนยันเภสัชกร, ยกเลิกบิล, พักบิล, ใบเสร็จ, ฉลาก
  reports/     ขย.9, ขย.11, ยาใกล้หมดอายุ
  serve.py     เซิร์ฟเวอร์สำหรับใช้งานจริง (waitress)
frontend/      หน้าขาย, หน้ารับยาเข้า, หน้านำเข้าข้อมูล (React + Vite)
scripts/windows/  ติดตั้ง, เปิดเซิร์ฟเวอร์, สำรองข้อมูล, เปิดหน้าร้านแบบ kiosk
```
